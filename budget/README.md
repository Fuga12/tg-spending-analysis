# Бот учёта совместного бюджета

Telegram-бот для двоих: пишешь «600 лимонад» — трата записана с суммой и
категорией. Разбор сообщений — Yandex AI Studio, суммы проверяются
детерминированно, без сети бот продолжает работать.

Реализовано по `../plan.md`. Расхождения с планом перечислены в конце.

## Что нужно

- Go 1.25.7+ (версию задаёт `goose`; сам код обходится возможностями 1.22)
- PostgreSQL 15+
- Токен бота от [@BotFather](https://t.me/BotFather)
- API-ключ Yandex AI Studio и `folder_id` каталога, к которому он привязан

## Настройка перед первым запуском

1. `cp .env.example .env` и заполнить `BOT_TOKEN`, `DATABASE_URL`,
   `ALLOWED_USER_IDS`, `YANDEX_API_KEY`, `YANDEX_FOLDER_ID`.
   Без любого из них бот не стартует.
2. Проверить доступные модели и поправить `LLM_MODEL` под фактический
   идентификатор Pro-модели:

   ```
   curl -H "Authorization: Api-Key $YANDEX_API_KEY" \
        -H "OpenAI-Project: $YANDEX_FOLDER_ID" \
        https://ai.api.cloud.yandex.net/v1/models
   ```

   Lite использовать не нужно: грант позволяет Pro, а качество разбора
   разговорного русского у него заметно выше.
3. `LLM_PRICE_PER_1K_RUB` выставить по актуальной странице тарифов —
   используется только для оценки в рублях в `/лимит`.
4. Накатить миграции: `make migrate-up`.
5. Проверить, что ключ живой, схема принимается и few-shot работает:

   ```
   go run ./cmd/classify-test "вчера пятёрочка 1200 и такси 400"
   ```

   Должны получиться два элемента с `days_ago=1` и непустой расход токенов.

## Запуск

```
make build      # bot и classify-test
make run        # бот в текущем терминале
make test       # тесты без базы
make test-db    # все тесты, включая интеграционные на настоящем Postgres
make lint       # gofmt + go vet
```

Локальная база для разработки поднимается через `make db-up`
(docker-compose, порт 5433). На проде база ставится пакетом, без Docker.

## Как это работает

**Быстрый путь.** Если в сообщении одна сумма, нет слов-триггеров
(«вчера», «и», запятая) и каждое значимое слово нашлось в словаре —
ответ собирается локально, без обращения к API. Словарь состоит из общей
затравки (82 слова) и личного кэша, который пополняется после каждого
разбора и после каждой ручной правки.

**Модель.** Всё остальное уходит в Yandex AI Studio со строгой JSON-схемой
и few-shot примерами. Список категорий в схеме генерируется из таблицы
`categories`, поэтому схема и база не разъезжаются.

**Проверка сумм.** Что бы ни вернула модель, каждая сумма обязана
присутствовать в тексте сообщения — сравнение точное, по `decimal`. Не
совпала — элемент отбрасывается. Модель раскладывает, но не считает.

**Если API недоступен.** Трата всё равно записывается: сумма — первая
найденная, описание — текст без суммы, категория — позже. Такие записи
подбирает воркер добора раз в 10 минут. Потеря записи не допускается ни при
каких условиях.

**Предохранители.** Три подряд ошибки сервиса закрывают сеть на
`LLM_BREAKER_COOLDOWN`. Месячный потолок токенов (`LLM_MONTHLY_TOKEN_BUDGET`)
на 80% шлёт владельцу разовое уведомление, на 100% прекращает сетевые
вызовы до следующего месяца. Это защита от собственных багов, а не от
расхода: нормальное использование грант не выбирает и близко. Если пришло
уведомление о 80% — где-то цикл, идти смотреть `/лимит`.

## Команды

| Команда | Что делает |
|---|---|
| `/месяц`, `/месяц 6` | Отчёт за текущий месяц или за июнь |
| `/день` | Траты за сегодня |
| `/лимит` | Расход токенов, ошибки по видам, состояние breaker |
| `/категории` | Список категорий |
| `/помощь` | Шпаргалка по формату |

Всё продублировано латиницей: `/month`, `/day`, `/usage`, `/categories`,
`/help`.

## Деплой

```
sudo useradd --system --home /opt/budget budget
sudo install -d -o budget -g budget /opt/budget
sudo install -o budget -g budget bot /opt/budget/bot
sudo install -o budget -g budget -m 600 .env /opt/budget/.env
sudo install -d -o budget -g budget /opt/budget/deploy
sudo install -o budget -g budget deploy/backup.sh /opt/budget/deploy/backup.sh

sudo cp deploy/budget-bot.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now budget-bot
journalctl -u budget-bot -f
```

Бэкап — крон раз в сутки, ротация 30 дней:

```
15 4 * * * /opt/budget/deploy/backup.sh >> /var/log/budget-backup.log 2>&1
```

Миграции накатываются отдельно (`make migrate-up`), а не при старте бота:
под `Restart=always` неудачная миграция превратилась бы в цикл падений.

## Расхождения с планом

Сознательные, каждое с причиной:

- **Docker для локальной базы.** §14 запрещает Docker; по прямому указанию
  заказчика база для разработки поднимается через `docker-compose.yml`.
  Деплой это не затрагивает: на проде один бинарь под systemd.
- **Блок «На кого ушло» (§10).** В плане формула говорит делить траты «на
  двоих» пополам, а пример вывода показывает их отдельной строкой «Общее», и
  суммы в примере сходятся именно так. Реализован вариант из примера.
- **upsert `word_map` (§8).** SQL из плана никогда не обновляет колонку
  `source`, из-за чего слово, однажды записанное моделью, не становилось бы
  ручным, и правка пользователя не получала бы приоритет. В коде `source`
  обновляется; смысл («ручная правка не перезатирается ответом модели»)
  сохранён.
- **Кириллические команды.** telebot не распознаёт `/месяц 6` как команду
  (его регулярка не знает кириллицы), поэтому такие сообщения разбираются
  вручную. Иначе `/месяц 6` записывалось бы тратой на 6 ₽.
- **Пометка дохода.** Для `kind='income'` строка ответа начинается с `↑` —
  в плане формат дохода не описан, а без пометки он читается как трата.
- **Уведомление о 80% потолка** помнится в памяти процесса: отдельной
  таблицы под этот флаг в схеме §3 нет. После рестарта в том же месяце
  уведомление может прийти повторно.
- **Доля быстрого пути в `/лимит`** считается с момента запуска процесса, а
  не за календарный месяц: сообщения, закрытые без API, нигде не
  сохраняются. В выводе это подписано.
- **Записи, которые модель разбирать отказывается**, воркер закрывает
  категорией «Прочее» — через два часа в очереди или сразу, если разбор
  заведомо бесполезен. §12 говорит только «обновить, снять флаг»; без этого
  такая запись перезапрашивалась бы каждые десять минут вечно, а breaker её
  не ловит: ошибки схемы и таймауты он сознательно не считает (§7).
- **Воркер дописывает траты, потерянные при сбое API.** Деградированный путь
  по §8 сохраняет только первую сумму, поэтому «пятёрочка 1200 и такси 400»
  при лежащем API дало бы одну запись. `raw_text` сохранён, и когда модель
  отвечает, недостающие траты записываются — иначе Definition of Done
  («не приводит к потере ни одной записи») не выполняется.
- **Строка «Партнёру»** в блоке «На кого ушло» появляется, пока второй
  участник не написал боту: в примере §10 такой строки нет, но отнести
  эти деньги к «Общему» значило бы соврать.
- **Напоминание** считает «сегодня уже писал» по `created_at`, а не по
  `spent_at`: тот, кто вечером записал вчерашние траты, ботом пользовался.
