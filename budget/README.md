# Бот учёта общего бюджета

Telegram-бот для группы: пишешь «600 лимонад» — трата записана с суммой и
категорией. Разбор сообщений — Yandex AI Studio, суммы проверяются
детерминированно, без сети бот продолжает работать.

**Состояние: идёт переделка.** Сервис был рассчитан ровно на двоих и имел
браузерный веб-интерфейс; сейчас он разбирается под группы до десяти человек
с интерфейсом внутри Telegram (Mini App). Схема, хранилище, отчёт, разбор и
бот переехали на группы; получателя трат модель называет по имени участника.

Группу пока нельзя создать из бота: это делается в приложении, а его ещё нет.
Завести первую можно только через `group.Service.Create`; дальше состав
собирается приглашениями, и отвечают на них прямо в боте. Что снесено и что
будет дальше — в конце файла.

## Что нужно

- Go 1.25.7+ (версию задаёт `goose`; сам код обходится возможностями 1.22)
- PostgreSQL 15+
- Токен бота от [@BotFather](https://t.me/BotFather)
- API-ключ Yandex AI Studio и `folder_id` каталога, к которому он привязан

## Настройка перед первым запуском

1. `cp .env.example .env` и заполнить `BOT_TOKEN`, `DATABASE_URL`,
   `YANDEX_API_KEY`, `YANDEX_FOLDER_ID`. Без любого из них бот не стартует.

   `ALLOWED_USER_IDS` необязателен: пусто — бот открыт для всех, кто его
   найдёт. Первый id в списке считается владельцем сервиса, ему уходят
   служебные уведомления.

   `APP_URL` тоже необязателен: пока приложения нет, бот не показывает ни
   кнопку под приветствием, ни кнопку меню. Кнопка, ведущая в никуда, хуже
   её отсутствия. Схема обязана быть https — иначе Telegram молча не откроет
   приложение, и бот не стартует, чтобы это было видно сразу.

2. Проверить доступные модели и поправить `LLM_MODEL` под фактический
   идентификатор Pro-модели:

   ```
   curl -H "Authorization: Api-Key $YANDEX_API_KEY" \
        -H "OpenAI-Project: $YANDEX_FOLDER_ID" \
        https://ai.api.cloud.yandex.net/v1/models
   ```

   Lite использовать не нужно: грант позволяет Pro, а качество разбора
   разговорного русского у него заметно выше.
3. `LLM_PRICE_PER_1K_RUB` выставить по актуальной странице тарифов —
   используется только для оценки расхода в рублях.
4. Накатить миграции: `make migrate-up`.
5. Проверить, что ключ живой, схема принимается и few-shot работает:

   ```
   go run ./cmd/classify-test -user <telegram id> "вчера пятёрочка 1200 и такси 400"
   ```

   Должны получиться два элемента с `days_ago=1` и непустой расход токенов.
   Человек должен состоять в группе: категории и словарь принадлежат ей.

## Запуск

```
make build      # собирает bot и classify-test
make run        # бот в текущем терминале
make test       # тесты без базы
make test-db    # все тесты, включая интеграционные (база budget_test)
make lint       # gofmt + go vet
```

Тесты бьют по **отдельной** базе `budget_test`: они делают `truncate`, и
указывать сюда боевую нельзя — один прогон стёр бы историю трат.

Локальная база для разработки поднимается через `make db-up`
(docker-compose, порт 5433). На проде база ставится пакетом, без Docker.

## Как это работает

**Быстрый путь.** Если в сообщении одна сумма, нет слов-триггеров
(«вчера», «и», запятая) и каждое значимое слово нашлось в словаре —
ответ собирается локально, без обращения к API. Словарь состоит из общей
затравки (82 слова) и личного кэша, который пополняется после каждого
разбора и после каждой ручной правки.

**Модель.** Всё остальное уходит в Yandex AI Studio со строгой JSON-схемой
и few-shot примерами. И схема, и промпт собираются из состояния группы:
список категорий — из `categories`, список получателей — из состава
участников, а примеры разбора называют людей их настоящими именами. Если про
получателя в сообщении не сказано, его даёт умолчание категории
(`default_member_id`), а не догадка модели; без умолчания трата уходит
плательщику. «На всех» — отдельное значение, оно означает общую трату.

**Корпус.** Полсотни настоящих сообщений с ожидаемым разбором лежат в
`internal/classify/testdata/corpus.json` и гоняются против фейковой модели.
Проверяется не модель, а всё вокруг неё: извлечение сумм, выбор быстрого
пути, разрешение получателей, умолчания, деградация. Правка промпта без такой
сетки — ставка вслепую.

**Проверка сумм.** Что бы ни вернула модель, каждая сумма обязана
присутствовать в тексте сообщения — сравнение точное, по `decimal`. Не
совпала — элемент отбрасывается. Модель раскладывает, но не считает.

**Если API недоступен.** Трата всё равно записывается: сумма — первая
найденная, описание — текст без суммы, категория — позже. Такие записи
подбирает воркер добора раз в 10 минут. Потеря записи не допускается ни при
каких условиях.

**Предохранители.** Три подряд ошибки сервиса закрывают сеть на
`LLM_BREAKER_COOLDOWN`. Месячный потолок токенов (`LLM_MONTHLY_TOKEN_BUDGET`)
на 80% шлёт владельцу разовое уведомление, на 100% прекращает сетевые
вызовы до следующего месяца. Это защита от собственных багов, а не от
расхода. Потолок пока общий на весь сервис — при открытом боте его придётся
сделать групповым.

## Группа

Бюджет принадлежит группе, а не человеку: один человек ведёт один бюджет,
и до десяти человек ведут общий. Десять — предел, на котором список
получателей ещё читается глазами, а не таблицей.

Зовёт администратор, и только того, кто уже писал боту: приглашение по логину
или телефону некуда доставить, а связать его с аккаунтом можно только на
честном слове. Приглашённому приходит сообщение с «принять» и «отказаться» —
человека, которого зовут, в группе ещё нет, и открывать ради одного нажатия
приложение незачем. Приглашение живёт неделю и занимает место в группе, пока
открыто: иначе десять приглашений разом дают одиннадцатого участника.

Группа не остаётся без администратора: последний не может ни выйти, ни
разжаловать себя. Ушедший не удаляется — на его строку ссылаются его траты,
и без неё история теряет плательщика. Вернувшемуся отдаётся та же строка,
чтобы он не раздвоился в отчёте.

## Команды

| Команда | Что делает |
|---|---|
| `/start` | Заводит пользователя, показывает состояние группы |
| `/помощь`, `/help` | Шпаргалка по формату |

Список намеренно минимален: всё, что можно показать интерфейсом, уезжает
в приложение. Любое сообщение без слэша — это трата.

Под каждой записанной тратой есть «удалить». Удаление мягкое, и на его месте
появляется «вернуть»: промах пальцем не должен стоить записи. «Исправить»
в боте нет намеренно — выбор категории, получателей и даты превращается
в чате в дерево из десятка нажатий, это работа приложения.

## Деплой

```
sudo useradd --system --home /opt/budget budget
sudo install -d -o budget -g budget /opt/budget
sudo install -o budget -g budget bot /opt/budget/bot
sudo install -o budget -g budget -m 600 .env /opt/budget/.env
sudo install -d -o budget -g budget /opt/budget/deploy
sudo install -o budget -g budget deploy/backup.sh /opt/budget/deploy/backup.sh

sudo cp deploy/budget-bot.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now budget-bot
journalctl -u budget-bot -f
```

Бэкап — крон раз в сутки, ротация 30 дней:

```
15 4 * * * /opt/budget/deploy/backup.sh >> /var/log/budget-backup.log 2>&1
```

Миграции накатываются отдельно (`make migrate-up`), а не при старте бота:
под `Restart=always` неудачная миграция превратилась бы в цикл падений.

## Переделка: что снесено и что дальше

**Снесено (фаза 0):** браузерный веб-интерфейс целиком вместе с сессиями и
одноразовыми ссылками входа; именованные корзины получателей; текстовые
отчёты в чате и все команды кроме двух; инлайн-кнопки под тратой; имена
участников из конфига.

**Сделано (фаза 2):** промпт и JSON-схема собираются из состава группы;
получатели разрешаются в участников по именам, совпавшие имена разводятся
номером; словарь запоминает получателя вместе с категорией; воркер добора
обходит группы по кругу, а не подряд по id. Корпус golden-тестов — в
`internal/classify/testdata/corpus.json`.

**Сделано (фаза 1):** чистая схема одной миграцией — `groups`, `members`
(участник — всегда Telegram-аккаунт, «один человек — одна группа»), `invites`,
`tx_recipients` вместо относительного `beneficiary`, `group_id` в категориях,
словаре и учёте токенов. Хранилище скоупится по группе типом, а не
параметром: `store.ForGroup(id).Expenses(…)`, и `group_id` подставляется сам.
Классификатор в этой фазе получателя ещё не определял.

**Сделано (фаза 4):** приглашения с ответом прямо в боте, роли, выход и
исключение, потолок в десять человек — все правила проверяются одной
транзакцией вместе с самим изменением. Напоминание переведено с
`ALLOWED_USER_IDS` на участников групп: при открытом боте whitelist пуст,
и по нему напоминание не уходило никому.

**Сделано (фаза 3):** `/start` зависит от состояния — нет группы, есть
группа, есть приложение; кнопка меню ведёт в Mini App (`APP_URL`); под
записанной тратой «удалить» и «вернуть»; у пакета `bot` появились тесты.

**Дальше:**

1. **Mini App.** Проверка `initData` по HMAC. Требует домена и TLS —
   это самая длинная внешняя зависимость, доставать стоит заранее.
2. **Отчёты.**

Браузерной ветки не будет: единственный вход — Mini App. Значит, dev-байпас
для локальной разработки обязателен, а проверку подписи нужно покрыть
тестами до того, как она станет единственной дверью.
