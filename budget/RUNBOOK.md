# Как это работает и что делать, когда сломается

Документ для того, кто обслуживает сервис. Про устройство кода — `README.md`,
здесь только эксплуатация: где что лежит, как выкатывать, что проверять,
когда «не работает».

Все команды — с боевой машины, `ssh kcv204@51.250.121.107`.

---

## Сначала — два долга, которые надо закрыть

**1. Сертификат истекает 19 ноября 2026, и продлевать его нечему.**

Он выпущен вручную и скопирован в `/etc/letsencrypt/live/` — без certbot, без
конфига продления, без таймера и без крона. Проверить:

```bash
echo | openssl s_client -servername kvl7312.ru -connect kvl7312.ru:443 2>/dev/null | openssl x509 -noout -dates
```

Когда он истечёт, **Mini App перестанет открываться полностью**: Telegram не
пускает приложение по невалидному TLS. Бот при этом продолжит принимать траты
в чате — снаружи это выглядит как «половина сервиса умерла без причины».

Лечится один раз и навсегда:

```bash
sudo apt-get install -y certbot python3-certbot-nginx
sudo certbot --nginx -d kvl7312.ru -d www.kvl7312.ru
```

Certbot перепропишет пути в конфиге nginx на свои и заведёт таймер продления.
После этого проверить, что таймер есть: `systemctl list-timers | grep certbot`.

**2. Приватный ключ сертификата читают все.**

```
-rw-rw-r-- 1 kcv204 kcv204 privkey.pem
```

Права `664` на приватном ключе означают, что его может прочитать любой
пользователь машины. Nginx читает ключ мастер-процессом от root, так что
ограничение ничего не сломает:

```bash
sudo chown root:root /etc/letsencrypt/live/privkey.pem && sudo chmod 600 /etc/letsencrypt/live/privkey.pem
sudo nginx -t && sudo systemctl reload nginx
```

Если ставить certbot по пункту 1 — он разложит ключи с правильными правами
сам, и этот пункт закроется заодно.

## Карта машины

Ubuntu 24.04, 2 ядра, 8 ГБ, диск 290 ГБ (занято ~16%).

| Что | Где | Чем управляется |
|---|---|---|
| Бот и Mini App | один процесс `/opt/budget/bot` | systemd, юнит `budget-bot` |
| База | контейнер `budget_postgres` (postgres:16) | docker compose из `~/tg-spending-analysis/budget` |
| Внешний вход | nginx, порты 80/443 | `/etc/nginx/sites-enabled/budget` |
| Исходники | `~/tg-spending-analysis` | git, ветка `groups` |
| Настройки | `/opt/budget/.env` | руками |
| Бэкапы | `/var/backups/budget` | крон root, 4:15 |

Порты:

```
0.0.0.0:443      nginx          — единственное, что смотрит наружу
0.0.0.0:80       nginx          — редирект на https
127.0.0.1:8081   bot            — Mini App, только через nginx
127.0.0.1:5433   docker-proxy   — база, только с самой машины
```

**Бот и приложение — один процесс.** У них общая база, общий конфиг и общее
время жизни; перезапуск `budget-bot` перезапускает и то, и другое.

**База в докере, а приложение — нет.** Так сложилось исторически; менять не
обязательно, но помнить надо: `docker compose down` уронит базу, и бот уйдёт
в цикл перезапусков.

## Выкатить изменения

```bash
cd ~/tg-spending-analysis && git pull --ff-only && cd budget
make build
sudo install -o budget -g budget bot /opt/budget/bot
sudo systemctl restart budget-bot
sudo journalctl -u budget-bot -n 20 --no-pager
```

`make build` собирает фронт (`npm ci && vite build`) и только потом бинарь.
Порядок обязателен: **фронт уезжает внутрь бинаря через `embed`**, и бинарь,
собранный до фронта, отдаст старое приложение — молча, без единой ошибки.

В логе после перезапуска должно быть четыре строки:

```
запущен ...
приложение слушает addr=127.0.0.1:8081 url=https://kvl7312.ru
кнопка меню ведёт в приложение ...
слежу за бэкапами ...
```

Если миграции изменились — накатить до перезапуска:

```bash
cd ~/tg-spending-analysis/budget && make migrate-up
```

Миграции сознательно не накатываются при старте бота: под `Restart=always`
неудачная миграция превратилась бы в цикл падений.

### Проверить, что фронт действительно обновился

```bash
curl -s https://kvl7312.ru/ | grep -oE 'index-[A-Za-z0-9_-]+\.js'
```

Имя файла содержит хеш содержимого. Не изменилось после сборки — значит
выкатился старый бинарь.

## Когда «не работает»

Диагностика по симптому. Каждый случай здесь уже случался.

### Бот не отвечает, но `systemctl` говорит `active`

Самый коварный отказ: процесс жив, перезапусков ноль, ошибок в логе нет, и
ни одного ответа. Значит, оборвался опрос Telegram.

```bash
sudo journalctl -u budget-bot -n 30 --no-pager -o cat
```

Если последняя запись старая и в ней ничего про ошибки — снять дамп горутин
и посмотреть, где стоит опрос:

```bash
sudo kill -QUIT $(systemctl show budget-bot -p MainPID --value)
sudo journalctl -u budget-bot --since '1 min ago' --no-pager -o cat | grep -A 10 'getUpdates'
```

`SIGQUIT` роняет процесс с трассировкой, systemd поднимает его заново, и
накопленные сообщения приходят разом.

Причина этого отказа исправлена — клиенту Telegram задан таймаут, — но если
он вернётся, узнавать его надо по этой связке признаков, а не по логу: лога
не будет.

### Бот в цикле перезапусков

```bash
systemctl show budget-bot -p NRestarts --value
sudo journalctl -u budget-bot -n 10 --no-pager -o cat
```

Почти всегда — база. `ping БД: connection refused` означает, что контейнер
не поднят:

```bash
cd ~/tg-spending-analysis/budget && sudo docker compose up -d postgres && sudo docker compose ps
```

### Mini App: «Открой приложение из Telegram»

Это **ответ сервера 401**: подпись не прошла. Смотреть в лог, там сказано,
что именно:

```bash
sudo journalctl -u budget-bot --since '10 min ago' --no-pager -o cat | grep 'не пустил'
```

- `подписи нет` — клиент не прислал заголовок. Фронт старый или в кэше
  вебвью; закрыть приложение полностью и открыть заново.
- `подпись не сошлась` — рядом печатается разбор: список полей и то, какой
  вариант проверочной строки подошёл бы. Чаще всего это чужой токен бота.
- `подпись просрочена` — часы на машине разъехались, `timedatectl`.

Проверить сервер напрямую, подписав запрос по-настоящему, можно скриптом из
раздела «Полезные команды» ниже.

### Mini App: 404 от nginx

404 отдаёт **сам nginx**, не приложение: будь там `proxy_pass`, при лежащем
боте пришло бы 502. Значит, домен обслуживает не тот блок.

```bash
sudo nginx -T | grep -nE 'server_name|proxy_pass|root '
```

Нужный блок — `/etc/nginx/sites-enabled/budget`, в нём один `location /`,
проксирующий всё на `127.0.0.1:8081`. Приложение отдаёт и API, и статику само;
разделять `/api` и файлы не надо.

Три вещи, которые ломают Mini App молча и потому стоят проверки:

- `X-Frame-Options` или `frame-ancestors` где-нибудь в общем конфиге. В
  Telegram Web приложение открывается во фрейме, и запрет встраивания даёт
  пустое окно без ошибки. На телефоне при этом всё работает.
- Перезаписанный список `proxy_set_header`. Подпись Telegram едет в
  `Authorization`; потеряется он — внутрь не попадёт никто.
- `client_max_body_size` меньше мегабайта. Сломается только загрузка фото
  профиля, остальное будет работать.

### Сборка падает на `npm ci`

Если `ETIMEDOUT` на `npm.yandex-team.ru` — в lock-файл попали адреса
внутреннего зеркала. Оно доступно там, где обновляли зависимости, и
недоступно здесь. Лечится на машине разработчика: переписать `resolved` на
`registry.npmjs.org`. В `web/.npmrc` реестр задан явно, чтобы это не
повторялось.

Опасность не в самой ошибке, а в том, что `make build` при этом падает
**после** сборки фронта, но до сборки бинаря — и `install` разложит прежний
бинарь. Всегда сверяйте хеш файла после выката.

### `git pull` упирается в локальные изменения

```bash
git checkout -- <файл> && git pull --ff-only
```

Если это `.env.example` или что-то из `web/` — там нет ваших данных, смело
откатывайте.

## Данные и бэкапы

База: `budget` в контейнере `budget_postgres`, том `budget_budget_pgdata`.
Пароль и адрес — в `DATABASE_URL` в `/opt/budget/.env`.

Бэкап делает крон root каждую ночь в 4:15:

```
15 4 * * * /opt/budget/deploy/backup.sh >> /var/log/budget-backup.log 2>&1
```

Скрипт не просто снимает дамп: он **разворачивает его во временную базу и
сверяет число записей** со снимком. Дамп, который не встаёт или встаёт
пустым, до каталога не доезжает. Хранится 30 дней.

Сторож внутри бота смотрит, что дампы свежие (`BACKUP_MAX_AGE`, по умолчанию
36 часов), и при пропаже пишет владельцу в Telegram. Если пришло «С бэкапами
беда» — смотреть `/var/log/budget-backup.log`.

Проверить руками:

```bash
sudo /opt/budget/deploy/backup.sh
sudo ls -lh /var/backups/budget/
```

### Восстановление

```bash
gunzip -c /var/backups/budget/budget-ГГГГ-ММ-ДД_ЧЧММ.sql.gz \
  | psql "$(sudo grep -oP '(?<=^DATABASE_URL=).*' /opt/budget/.env)"
```

Дамп сделан с `--clean --if-exists`, поэтому накатывается на непустую базу.
Бот на время восстановления лучше остановить: `sudo systemctl stop budget-bot`.

## Настройки

`/opt/budget/.env`, читается при старте. После правки — `systemctl restart
budget-bot`. Образец со всеми пояснениями — `.env.example` в репозитории.

Что стоит знать про конкретные:

| Переменная | Смысл |
|---|---|
| `ALLOWED_USER_IDS` | Кого вообще пускать. **Пусто = бот открыт для всех.** Приглашённый, которого нет в списке, получит уведомление, но внутрь не попадёт — ни в бота, ни в приложение |
| `OWNER_ID` | Кому уходят служебные уведомления. Отдельно от списка: при открытом боте список пуст, и владельца в нём нет |
| `APP_URL` | Адрес Mini App. Обязан быть `https://`, иначе бот **не стартует** — это намеренно, молча не открывающаяся кнопка хуже отказа |
| `APP_LISTEN` | Где слушает приложение. Пусто — не поднимается |
| `APP_DEV_USER_ID` | **В проде быть не должно.** Пускает без подписи Telegram. При старте бот об этом кричит в лог |
| `LLM_MONTHLY_TOKEN_BUDGET` | Общий потолок токенов. Защита от собственных багов, а не от расхода |
| `LLM_GROUP_TOKEN_BUDGET` | Потолок на группу. При открытом боте обязателен: иначе одна активная группа выберет грант целиком |
| `MESSAGES_PER_DAY` | Потолок сообщений на человека в сутки. Счётчик в памяти, перезапуск его обнуляет |

Секреты в логи не попадают: ошибка telebot содержит URL с токеном, поэтому
она пишется без тела; в уведомлении о сбое бэкапа печатается команда до
подстановки переменных.

## Полезные команды

```bash
# Лог живьём
sudo journalctl -u budget-bot -f

# Что сейчас с сервисом
systemctl status budget-bot --no-pager
sudo ss -ltnp | grep -E ':(443|8081|5433)\b'
sudo docker compose -f ~/tg-spending-analysis/budget/docker-compose.yml ps

# Заглянуть в базу
sudo docker exec -it budget_postgres psql -U budget -d budget

# Проверить API с настоящей подписью (подставит токен сам, наружу не печатает)
sudo python3 - <<'PY'
import hashlib, hmac, json, time, urllib.parse, subprocess
env = {k.strip(): v.strip().strip('"').strip("'")
       for k, v in (l.split('=', 1) for l in open('/opt/budget/.env')
                    if '=' in l and not l.startswith('#'))}
uid = int(env.get('OWNER_ID') or env['ALLOWED_USER_IDS'].split(',')[0])
f = {'auth_date': str(int(time.time())),
     'user': json.dumps({'id': uid, 'first_name': 'Проверка'}, ensure_ascii=False)}
dcs = '\n'.join(f'{k}={v}' for k, v in sorted(f.items()))
sec = hmac.new(b'WebAppData', env['BOT_TOKEN'].encode(), hashlib.sha256).digest()
f['hash'] = hmac.new(sec, dcs.encode(), hashlib.sha256).hexdigest()
print(subprocess.run(['curl', '-s', '-w', '\n>>> %{http_code}',
                      '-H', 'Authorization: tma ' + urllib.parse.urlencode(f),
                      'https://kvl7312.ru/api/state'],
                     capture_output=True, text=True).stdout)
PY
```

Ответ `200` — сервер в порядке, дело в клиенте. `401` — в подписи.
`403` — подпись верна, но id не в whitelist.

## Что осталось незакрытым

Кроме двух долгов в начале документа:

**Фронт почти не проверялся живьём.** Бэкенд под тестами плотно (`make
test-db`), фронт — только сборкой и типами. Ошибки в нём находятся глазами.

**Извлечение сумм не отличает вес от денег.** «3.5кг баранины 1400» разберётся
верно случайно, а «взял 2кг по 300» — нет. Правило «число, за которым сразу
идёт единица измерения, — не сумма» не написано.

**Счётчик сообщений живёт в памяти.** Перезапуск его обнуляет. Осознанно: он
защищает от того, кто долбит бота прямо сейчас, а этот сценарий перезапуск и
так прерывает.

**Второй экземпляр бота запускать нельзя.** Telegram отдаёт обновления одному
потребителю; два процесса с одним токеном будут воровать сообщения друг у
друга. Перед запуском копии — гасить основную.

**Docker-вариант описан, но на этой машине не используется.** `Dockerfile` и
`docker-compose.yml` собирают всё в образе и рабочие, но сервис живёт под
systemd. Если переезжать — помнить, что внутри контейнера `APP_LISTEN` обязан
быть `0.0.0.0:8081`: на `127.0.0.1` приложение слушает петлю самого
контейнера, и проброшенный порт до него не достанет.
