# План переделки: от бота на двоих к группам

Что осталось сделать. Фаза 0 (снос) завершена — её содержимое в конце файла,
для справки.

`plan.md`, `webapp.md` и `webapp-design.md` описывают систему, которой больше
нет. Из них живым остаётся только раздел дизайна в `webapp-design.md`
(палитра, правила графиков) — он воплощён в `web/src/Charts.tsx` и
`styles.css` и переиспользуется. Остальное — исторические документы.

## Принятые решения

| Решение | Следствие |
|---|---|
| Группа до 10 человек | относительный `beneficiary` невыразим, нужен абсолютный |
| Участник — всегда Telegram-аккаунт | `members.user_id NOT NULL` |
| Один человек — одна группа | `unique(members.user_id)` |
| Приглашает админ, но только того, кто стартовал бота | внешний ключ `invites.invitee_user_id → users` и есть это правило |
| Именованных корзин («дети») нет | получатель — только участник |
| Браузерной ветки нет, только Mini App | единственный вход — `initData`, обратной двери не остаётся |
| Whitelist необязателен, пока включён | `ALLOWED_USER_IDS` пуст = открытый бот |
| Тарификация групп — потом | но `group_id` в `llm_usage` закладывается сразу |
| Минимум команд | всё, что можно показать интерфейсом, уезжает в приложение |
| Имя из Telegram при заведении, дальше правится в приложении | `EnsureUser` не перезатирает |

## Фаза 1. Фундамент

Данных нет, поэтому миграции 0001–0009 схлопываются в одну чистую.

**1.1 Схема**

```
users         (id telegram, name, avatar, avatar_set_at, created_at)
groups        (id, name, created_at)
members       (id, group_id → groups, user_id → users NOT NULL,
               role admin|member, joined_at,
               unique(user_id))
invites       (id, group_id, invitee_user_id → users, invited_by → users,
               created_at, expires_at, accepted_at, declined_at)
categories    (id, group_id, name, hint, template_key, default_member_id,
               sort_order, unique(group_id, name))
transactions  (id, group_id, payer_member_id, kind, amount, description,
               category_id, raw_text, spent_at, created_at, updated_at,
               deleted_at, needs_classification, needs_review)
tx_recipients (transaction_id, member_id)   -- пусто = на всю группу
word_seed     (word, template_key)          -- глобальная
word_map      (group_id, user_id, word, category_id, member_id,
               source, hits, updated_at)
llm_usage     (id, group_id, model, prompt_tokens, completion_tokens,
               ok, error_kind, created_at)
```

`template_key` у категории обязателен: затравка словаря общая на всех и не
может ссылаться на `category_id` конкретной группы.

**1.2 Скоупнутое хранилище.** `store.ForGroup(id).Expenses(ctx, from, to)`
вместо параметра `groupID` в сорока с лишним методах. Запрос без фильтра
нельзя написать по невнимательности — только намеренно, через отдельный
административный хендл. Это главная защита от худшего бага мультитенантности.

**1.3 Хранилище под новую модель:** транзакции с получателями, словарь,
отчётные выборки, учёт токенов.

**1.4 Отчёт на `tx_recipients`.** Удаляются `partnerOf`, корзина «Партнёру»,
switch по `beneficiary`. Логику `ComparableRange` (сопоставимый отрезок
прошлого месяца) перенести как есть — она продумана и остаётся верной.

**1.5 Классификатор временно перестаёт определять получателя.** Каждая
трата пишется с получателем «плательщик». Это держит дерево собранным и
откладывает работу над промптом до фазы 2.

**Готово когда:** тесты отчёта проходят на группе из пяти человек, и ни один
метод хранилища не принимает `groupID` аргументом.

## Фаза 2. Категоризатор

**2.1 Корпус golden-тестов — первым делом.** Полсотни реальных сообщений с
ожидаемым разбором, против фейкового LLM. Без него любая правка промпта —
ставка вслепую: чинишь «пиво», ломаешь «вчера пятёрочка 1200 и такси 400».

**2.2 Промпт собирается из состояния группы:** enum категорий (уже так) и
enum участников по именам. Few-shot перестаёт быть константой с «ей».

**2.3 Валидация** разрешает имена участников в `member_id`; сохраняются оба
правила — сумма обязана быть в тексте, и `beneficiary_stated=false` отдаёт
получателя умолчанию категории (`default_member_id`).

**2.4 Словарь:** `word_map` с `group_id`, `ForgetLLMWords` по группе.

**2.5 Воркер добора:** справедливый обход групп. Сейчас берёт 20 записей
`order by id` — одна активная группа забьёт батч и остальные будут ждать.

**Готово когда:** корпус зелёный, разбор на группе из троих осмысленно
раскладывает получателей.

## Фаза 3. Бот

**3.1** `/start` зависит от состояния: нет группы → «создайте группу или
попросите администратора добавить вас»; есть → кнопка приложения.

**3.2** Кнопка меню на Mini App (`setChatMenuButton` или BotFather).

**3.3** Под записанной тратой — «удалить». Кнопка «исправить» требует URL
приложения и приезжает в фазе 5.

**3.4** Вернуть тесты пакета `bot` — сейчас их нет ни одного: `transactionLine`,
`Money`, `dayLabel`, разбор кириллических команд.

## Фаза 4. Группы и приглашения

**4.1** Хранилище: создание группы, участники, приглашения.
**4.2** Создание группы раскатывает категории из шаблона (`template_key`).
**4.3** Пригласить, принять, отклонить, выйти, исключить.
**4.4** Роли и правила: последний администратор не может выйти или разжаловать
себя; группа не остаётся без админа; потолок 10 участников.
**4.5** Уведомление в бот о полученном приглашении.
**4.6** `reminder` переводится с `cfg.AllowedUserIDs` на участников группы —
сейчас при выключенном whitelist он не напомнит никому.

## Фаза 5. Mini App

**5.1 Проверка `initData` по HMAC и тесты к ней — до всего остального.**
Браузерной ветки нет, и ошибка здесь означает, что внутрь не попасть ничем.

**5.2** Dev-байпас `APP_DEV_USER_ID`: обязателен, не удобство. Громкий лог
при старте, чтобы не уехал в прод молча.

**5.3** `internal/app`: сервер, `embed`, маршруты. Один пакет — дублировать
нечего, браузерной ветки не будет.

**5.4** Домен, TLS, регистрация Mini App. **Самая длинная внешняя
зависимость во всём плане — доставать заранее, не дожидаясь фазы 5.**

**5.5** Фронт заново: `api.ts`, `App`, экраны трат, редактирования, группы,
участников, категорий. Переиспользуются `Charts.tsx`, `format.ts`,
`styles.css`.

**5.6** Палитра на N участников: сейчас три жёстких слота («я», «партнёр»,
«общее»). Правило «смотрящий всегда первый слот» сохранить.

## Фаза 7. Эксплуатация

- Квота токенов на группу и лимит сообщений на человека. Отложено сознательно,
  но до открытия бота обязательно: сейчас чужие сообщения жгут ваш грант.
- `OWNER_ID` отдельной переменной — сейчас владелец это первый id whitelist,
  а при открытом боте whitelist пуст и уведомления уходить некому.
- Ссылки на разделы `plan.md` (`§8`, `§10`, …) в комментариях кода после
  переделки указывают на документ, который больше не описывает систему.
  Либо переписать ссылки, либо снять.
